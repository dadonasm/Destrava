Um pendrive só. Ele faz: FICHA da máquina (nota, hardware, programas pesados, sistema ideal, melhorias com
"aplicar"), BACKUP organizado com certificado, e guarda o HISTÓRICO de cada máquina atendida.

PREPARAR O PENDRIVE (uma vez)
  1) Instale o Ventoy no pendrive (ventoy.net). Use 16 GB ou mais.
  2) Copie para ele, como arquivos comuns:  o ISO do Zorin OS  e esta pasta  Destrava  (descompactada).
  3) Para o Windows rodar SEM instalar nada: baixe "Windows embeddable package (64-bit)" em
     python.org/downloads/windows e extraia dentro de  Destrava\runtime  (precisa existir runtime\python.exe).
  Resultado: o pendrive serve para (a) iniciar o Zorin e (b) rodar o Destrava! direto no Windows.

USAR
  A) Windows LIGADO (ficha completa: boot, programas de inicialização, programas pesados, aplicar melhorias):
     abra o pendrive > Destrava > duplo clique em  Iniciar-Windows.bat  (pede administrador).
     Home > "Permitir e analisar esta máquina". As fichas vão para  Destrava\maquinas  no pendrive.
  B) Backup seguro: inicie o PC pelo pendrive no Zorin ("Experimentar"), monte os discos (clique neles no
     gerenciador de arquivos) e rode  sudo sh Iniciar-Linux.sh  dentro da pasta Destrava.
     Na Home dá para rodar a ficha também (hardware e disco; boot e inicialização do Windows não são medidos no Live).
  O mesmo botão "Backup" (gaveta lateral) leva aos 6 passos: origem/destino, checagens, seleção, cópia, verificação, certificado.

RODAR SEM PENDRIVE (servidor da loja)
  Um computador da loja roda o servidor (Django em Docker, porta 8080) e entrega o programa a qualquer computador, na bancada ou no cliente.
  Fichas, históricos e termos ficam NO SERVIDOR; o computador atendido não guarda nada.
  PREPARAR (uma vez, no computador do servidor, dentro da pasta do projeto):
    1) python3 nucleo/baixar_runtimes.py     baixa o Python fixo (3.12.10) para Windows, Mac e Linux
    2) docker compose up -d web              sobe o servidor (porta 8080, só neste computador)
    3) docker compose exec web python manage.py nova_chave "Seu nome"
       cria a chave do técnico. GUARDE: ela aparece uma única vez. (listar_chaves e revogar_chave "Nome" também existem)
    4) Pela internet:  docker compose --profile internet up -d   e o endereço sai em
       docker compose logs tunel | grep trycloudflare      (temporário: muda a cada reinício)
       Endereço fixo: crie um túnel na Cloudflare (precisa de domínio), ponha CLOUDFLARE_TUNNEL_TOKEN e DESTRAVA_URL_PUBLICA
       num arquivo .env e use --profile internet-fixo.
  USAR: abra o endereço do servidor no navegador do computador atendido e siga a página:
    Windows (PowerShell):    irm <endereço>/iniciar.ps1 | iex
    Mac e Linux (Terminal):  curl -fsSL <endereço>/iniciar.sh | sh
    Digite a chave do técnico. Ao terminar, clique em "Encerrar" no topo: envia o que faltar e apaga tudo do computador.
    Sem internet no meio do serviço, as alterações ficam "pendentes" e vão sozinhas quando a conexão voltar.
  ATENÇÃO: o servidor só funciona com o computador dele ligado e acordado. Faça backup da pasta servidor-dados/
    (dados dos clientes e chaves). O termo no modo servidor avisa o cliente de que os dados ficam no servidor da D&D.

TESTAR NO PRÓPRIO COMPUTADOR (desenvolvimento)
  O programa (motor) fica em nucleo/; os lançadores da raiz já apontam para lá. Veja README-DEV.md.
  Mac/Linux: sh testar-local.sh       Windows: Testar-Windows.bat       (os dados de teste ficam fora do pendrive)
  Reproduzir outra máquina: na ficha, Detalhes técnicos > "Exportar dados para suporte" grava um arquivo na Área de
    Trabalho. Em outro computador:  sh testar-local.sh --coleta-salva arquivo.json   (as ações são só simuladas)
  Testes automáticos:  python3 -m unittest discover tests

NOTA E "OUTCOME": a nota (0 a 100) resume CPU, memória, disco, tempo de resposta, boot e programas ao ligar.
  Depois de "aplicar melhorias", o programa mede de novo e mostra ANTES -> DEPOIS (boot e inicialização só melhoram
  de vez após reiniciar). É a prova do resultado entregue ao cliente.

O QUE "APLICAR" FAZ (sempre com sua confirmação, e com Desfazer)
  Windows: desativa programas de inicialização marcados (mesmo método do Gerenciador de Tarefas), reduz transparência e
  animações, limpa temporários com mais de 3 dias. Linux: oculta itens de autostart. NADA toca em documentos.
  Trocar HDD por SSD, RAM e bateria aparecem como recomendações para o técnico (hardware).

SISTEMA IDEAL: nota ESTIMADA do sistema recém-instalado nesta máquina (Windows 10/11, Zorin Core/Lite, Mint XFCE,
  Lubuntu), com compatibilidade (Windows 11: UEFI, Secure Boot, TPM 2.0, 4 GB, geração do processador - heurística).
  Windows 10 aparece com o aviso de fim do suporte gratuito (14/10/2025).

LIMITES HONESTOS
  * Testado em Linux real e com dados de Windows SIMULADOS. NÃO testado em Windows real: a coleta usa PowerShell nativo;
    se algum campo vier vazio, a nota é calculada só com o que foi medido (aparece "nota sobre X% dos critérios").
  * Tempo de boot do Windows vem do log de desempenho do próprio Windows (precisa de administrador e do log ativo).
  * Medições de velocidade são indicativas e variam com o que está aberto. Notas servem para comparar antes/depois.
  * Slots de RAM e saúde do disco exigem administrador/root.
  * Veja também as notas de backup: BitLocker, Inicialização rápida, OneDrive só na nuvem.
